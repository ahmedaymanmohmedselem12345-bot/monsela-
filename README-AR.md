# Monsela — التحديث المحسّن — 19 أكتوبر 2026

هذه نسخة مطوّرة من ملفاتك الأصلية، وليست إعادة بناء للمتجر. الربط بمشروع Supabase وأسماء الجداول والدوال الحالية محفوظ. لم يتم تعديل قاعدة البيانات الحية أو نشر ملفات على Vercel.

## اقرأ هذه النقطة أولًا

التحديث نجح في 81 اختبارًا محليًا للكود والحسابات ومحاكاة الطلب والصلاحيات والبناء. لم يجرِ اختبار متصفح فعلي أو إرسال طلب لقاعدة البيانات الحقيقية؛ تم رفض وصول متصفح الاختبار. لهذا النسخة مرشحة للنشر بعد خطوات التحقق أدناه، وليست شهادة أمان أو ضمانًا لتوافق قاعدة البيانات.

## خطواتك بالترتيب

1. احتفظ بالملف `backup-original.zip` على جهازك؛ هو الملف الأصلي الذي أرسلته بدون تعديل. احتفظ كذلك بنسخة كاملة من قاعدة البيانات وملفات Storage بوسيلة النسخ الاحتياطي التي تستخدمها حاليًا. زر تصدير البيانات في لوحة الإدارة لا يغني عن النسخة الكاملة.
2. افتح Supabase > SQL Editor، وشغّل محتوى `database/00-export-security-audit.sql`. الملف للقراءة فقط؛ يرجع تعريفات الجداول والدوال وسياسات الوصول، دون صفوف العملاء والطلبات. صدّر النتيجة JSON وراجعها قبل مشاركتها، لأن دالة قديمة ربما تحتوي قيمًا سرية مكتوبة داخلها.
3. أرسل نتيجة الفحص لاستكمال مراجعة `place_order` والصلاحيات قبل اعتماد التحديث للإنتاج. تعديل الواجهة وحده لا يمنع تغيير الأسعار أو الوصول المباشر لقاعدة البيانات.
4. لتفعيل لوحة الإدارة الجديدة: افتح `database/01-admin-access.sql` واستبدل `OWNER_EMAIL_HERE` ببريد حساب المدير الحالي المؤكد في Supabase، ثم شغّل الملف كله. لا تدخل كلمة مرور ولا تنشئ حسابًا جديدًا. السكريبت يتوقف ويرجع المعاملة كاملة إن لم يجد الحساب المؤكد. لا يغيّر منتجاتك أو طلباتك أو سياسات الجداول الحالية.
5. في إعدادات المصادقة في Supabase، أضف رابط الموقع الفعلي ورابطي `/index.html` و`/reset-password.html` إلى عناوين إعادة التوجيه المسموحة. جهّز إرسال البريد واختبر وصول رسالة إنشاء الحساب والاستعادة. تفعيل تأكيد البريد للحسابات الجديدة يتم من إعدادات Supabase، وليس من JavaScript.
6. من لوحة الإدارة راجع مناطق التوصيل وأسعارها، وحد الشحن المجاني، وسعر تغليف الهدية، وبيانات التحويل. لا توجد أسعار توصيل وهمية مضافة. لو المناطق فارغة، الموقع يوجّه العميل للتواصل بدل عرض تكلفة نهائية مضللة.
7. ارفع ملفات المصدر في فرع اختبار على GitHub أولًا. هذه النسخة تستخدم `package.json` و`build.mjs` و`vercel.json`: البناء هو `npm run build` ومجلد النتيجة `dist` وإعداد Framework هو Other. لا ترفع ملف `backup-original.zip`. احتفظ بمجلدي database وtests والتعليمات خارج النشر العام؛ البناء ينسخ فقط ملفات الموقع المسموح بها.
8. اختبر رابط المعاينة قبل اعتماده للمتجر الحي: منتج عادي، منتج بمقاس/لون، كوبون، شحن مجاني، طلب كضيف، حساب قديم بالموبايل، حساب جديد بالبريد، استعادة كلمة المرور، منع حساب العميل من الإدارة، والطلب من موبايل وكمبيوتر.
9. اعتمد النشر بعد نجاح مراجعة قاعدة البيانات واختبار المعاينة. لا تجرّب دفعًا حقيقيًا لإتمام الاختبار.

## التغييرات المهمة

- الطلب متاح كضيف بدون حساب، مع عنوان واضح ومنطقة توصيل وموافقة على الشروط.
- الشحن المجاني يعمل على قيمة المنتجات قبل خصم الكوبون. نفس القاعدة مطبقة في السلة وحساب الإجمالي، ويجب التأكد أن دالة الخادم تطبقها أيضًا.
- تحديث السعر والمخزون والتوصيل قبل الإرسال، وإيقاف التأكيد عند تغيّر القيمة حتى يراجعها العميل.
- إعادة فحص الكوبون من الخادم، بدل استخدام قيمة السلة القديمة كحد أدنى للخصم.
- حدّ المخزون يشمل الكميات المكررة لنفس المقاس عبر ألوان الزجاجة؛ إعادة المنتجات المحفوظة للسلة تخضع لنفس القواعد.
- تطبيع أرقام الموبايل العربية والإنجليزية وصيغة +20، ورفض الأرقام غير الصحيحة.
- عدم مسح السلة عند فشل الطلب، ومنع الضغط المكرر أثناء الإرسال.
- عند انقطاع الشبكة بعد الإرسال، يمنع تكرار المحاولة في نفس التبويب حتى التواصل مع المتجر للتحقق؛ لا يوجد بعد ضمان تكرار آمن عبر الخادم أو الأجهزة. هذه النقطة تحتاج مفتاح idempotency في قاعدة البيانات بعد مراجعة تعريف `place_order`.
- صفحة نجاح برقم الطلب ونسخه وتتبع الطلب ورابط واتساب اختياري؛ لا يتم فتح واتساب تلقائيًا أو إرسال رسالة للعميل.
- الحسابات الجديدة تستخدم بريدًا حقيقيًا مع مسار لاستعادة كلمة المرور؛ الحسابات القديمة تحتفظ بدخولها بالموبايل وكلمة المرور. ملكية رقم الهاتف ليست موثّقة برسالة SMS.
- حسابات الموبايل القديمة لا تملك بريد استعادة حقيقيًا؛ رابط المساعدة يوجّه لخدمة العملاء للتحقق من الملكية. لا يوجد تجاوز تلقائي لكلمات المرور.
- إلغاء نوافذ الترحيب والكوبونات الافتراضية والتذكير المتكرر بالتسجيل.
- صلاحية الإدارة تتحقق من دالة `monsela_is_admin`، وغيابها أو رفضها يمنع فتح اللوحة. مكونات اللوحة الإضافية لا تبدأ طلباتها قبل تحقق الصلاحية.
- تحسين ترميز النصوص وروابط واتساب وتصدير CSV، وتصدير بيانات الإدارة على صفحات لتقليل احتمال الاقتصاص عند 1000 صف.
- تحسينات لحجم حقول الموبايل، مناطق الضغط، نوافذ الطلب، التركيز بلوحة المفاتيح ورسائل الحالة.
- استخراج صورة العلامة الموجودة إلى ملف مستقل لتقليل HTML وإضافتها لصورة المشاركة. لا توجد صور منتجات وهمية.
- إعداد بناء يمنع نشر النسخ القديمة والملفات الداخلية، مع ترويسات حماية أساسية.

## ما لم يُفعّل أو يُتحقق منه

- سياسات RLS، صلاحيات الدوال، التحقق الخادمي من الإجمالي والمخزون، والتوافق الفعلي لطلبات الضيوف: تحتاج نتيجة فحص Supabase. ملف صلاحية الإدارة لا يصلح هذه الأجزاء تلقائيًا.
- الحماية الكاملة من تكرار الطلب أو تسابق خصم المخزون تحتاج معاملة خادمية وقفل/مفتاح طلب؛ لم نخمن تعريفات الجداول أو نستبدل الدالة الحالية.
- إرسال البريد وتأكيده يحتاج إعدادات المشروع الحقيقية واختبار الوصول. لم تُرسل رسائل من جلسة التطوير.
- Meta Pixel وGA4 غير مفعلين لعدم توافر معرفات حساباتك. يوجد مدخل أحداث محلي `dataLayer` للتوصيل لاحقًا: `monsela_add_to_cart` و`monsela_begin_checkout` و`monsela_order_submitted`. حدث الطلب ليس دفعًا مؤكدًا، فلا تربطه تلقائيًا بمبيعات مدفوعة.
- الإنجليزية الجزئية الأصلية محفوظة؛ النسخة لا تدّعي اكتمال ترجمة كل الرسائل الديناميكية. صفحات المنتجات لا تزال ضمن الصفحة الرئيسية، وليست صفحات SEO منفصلة مبنية على الخادم.
- سياسات الإرجاع والشروط التجارية الأصلية لم تحصل على مراجعة قانونية ضمن هذا التحديث.
- لا يوجد تغيير متعمد لتفعيل معمل تركيب العطر المخفي أصلًا.

## للمطور: التشغيل المحلي

يتطلب Node.js 20 أو أحدث. لا توجد حزم npm خارجية لازمة للبناء.

```bash
npm test
npm run build
python -m http.server 4173 --directory dist
```

الاختبارات تستخدم بيانات صناعية في الذاكرة ولا تتصل بـSupabase ولا تنشئ طلبات حقيقية. فتح الموقع الفعلي سيستخدم إعدادات Supabase الأصلية؛ اختبارات الطلب النهائية تُجرى على بيئة معاينة وقاعدة اختبار مناسبة.

## الرجوع للإصدار السابق

لو ظهر خلل في المعاينة لا تعتمد النشر. ارجع إلى إصدار Vercel السابق أو استعد ملفات `backup-original.zip` في الفرع المناسب. إضافة جدول صلاحية الإدارة لا تغيّر عمل الواجهة القديمة؛ لا تحذف جداول المنتجات أو الطلبات ولا تشغّل DROP DATABASE.
